# 📋 Problem Statement 1: Log Parser

**File:** `basics.py`

## 📝 Problem Description

You are given a list of log messages generated by an application during execution. Each log entry is a string that starts with a severity level followed by a colon.

**Valid Severity Levels:**

- `INFO`
- `WARN`
- `ERROR`

## 🎯 Task

Write a program that:

1. Iterates over the logs
2. Counts how many logs belong to each severity level
3. Ignores any malformed log entry (no colon or empty string)

## 📥 Input

```python
logs = [
    "INFO: Application started",
    "WARN: Disk usage high",
    "ERROR: Unable to connect to DB",
    "INFO: Retrying connection",
    "INVALID LOG",
    "",
    "ERROR: Timeout occurred"
]
```

## 📤 Output

```python
{
    "INFO": 2,
    "WARN": 1,
    "ERROR": 2
}
```

# 🧩 Problem Statement 2: API Response Validator

**File:** `functions.py`

## 📝 Problem Description

You are validating API responses received from a backend service. Each response is a dictionary with:

- `status_code` (int)
- `response_time` (float, in ms)

## ✅ Validation Rules

A response is **VALID** if:

- Status code is `200` or `201`
- Response time is ≤ `500` ms

Anything else is **INVALID**. Missing or malformed fields should not crash the program.

## 📥 Input

```python
responses = [
    {"status_code": 200, "response_time": 320},
    {"status_code": 500, "response_time": 100},
    {"status_code": 201, "response_time": 650},
    {"status_code": 200},
    {"status_code": 201, "response_time": 450}
]
```

## 📤 Output

```python
{
    "VALID": 2,
    "INVALID": 3
}
```

# 📊 Problem Statement 3: Test Coverage Comparator

**File:** `collections.py`

## 📝 Problem Description

You are comparing UI test coverage and API test coverage for a release. Each coverage list contains test names.

## 🎯 Task

Write a program that:

1. Finds tests covered by both UI and API
2. Finds tests covered only by UI
3. Finds tests covered only by API
4. Returns the result as a dictionary

## 📥 Input

```python
ui_tests = ["login", "signup", "logout", "profile"]
api_tests = ["login", "logout", "settings"]
```

## 📤 Output

```python
{
    "common": {"login", "logout"},
    "ui_only": {"signup", "profile"},
    "api_only": {"settings"}
}
```

# 🧩 Problem Statement 4: User Management Model

**File:** `user.py`

## 📝 Problem Description

You are building a simple user management model for an application. Implement the classes and composition described below.

## 🔹 Requirements

1. Base Class: `User`
   - Attributes: `username: str`, `email: str`, `active: bool`
   - Behavior:
     - `is_active()` → returns `bool`
     - `deactivate()` → sets the user inactive
     - `get_display_name()` → returns `<username> (<email>)`

2. Child Class: `AdminUser` (inherits from `User`)
   - Additional attribute: `role: str` (default = `"admin"`)
   - Overridden behavior:
     - `is_active()` → admin is active only if the base user is active AND `role == "admin"`
   - Additional behavior:
     - `is_admin()` → always returns `True`

3. Composition: `Profile`
   - Attributes: `full_name: str`, `age: int`
   - Rule: `age` cannot be negative

4. Composition usage
   - Every `User` has a `Profile` (passed during user creation)
   - `User` exposes: `get_profile_summary()` → returns `<full_name> | Age: <age>`
